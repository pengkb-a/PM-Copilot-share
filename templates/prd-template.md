# PRD 模板

> 通用模板 + 报表类需求专用模板。生成 PRD 时按此结构，仅输出需要的章节。
> 对应的技能版规范见 `.claude/skills/prd-template/SKILL.md`。

## 标题层级规则

为适配飞书文档导入：

1. **不使用 `#`**（飞书不支持 H1，去掉文档标题行）
2. **章节标题用 `##`**（飞书导入后显示为 H1，如 `## 修订记录`）
3. **子章节用 `###`**（飞书导入后显示为 H2，如 `### 需求背景`）
4. **标题不带序号**（不写 `## 1. 修订记录`，直接写 `## 修订记录`）
5. **功能模块标题用 `###`**，不带序号，直接用功能名称（如 `### 订单列表（变更）`）

## 必选章节

每份 PRD 都必须包含：
- 修订记录
- 需求概述（需求背景 + 需求目标 + 本期功能清单）
- 需求详情

## 按需章节

| 章节 | 包含条件 |
|------|---------|
| 名词解释 | 涉及读者可能不熟悉的专业术语或新概念 |
| 需求价值 & 预估收益 | 需要说明业务价值时 |
| 需求风险描述 | 存在明显风险或不确定性 |
| 功能框架 | 涉及多模块、多系统或复杂流程 |
| 协同需求 | 需要跨系统/跨部门协作 |
| 待办项 | 本期不做但后续需要迭代的事项 |

## 完整章节骨架

```markdown
## 修订记录

> 版本号规则：创建文档用 V1.0，每次修订 +0.1（V1.1、V1.2...）
> 修订内容用简短动词短语，如"补充 XX 说明""修正 XX 逻辑""新增 XX 章节"

| 版本号 | 修订人 | 修订时间 | 修订内容 |
|--------|--------|----------|----------|
| V1.0   | [姓名]  | [日期]   | 创建文档 |

## 名词解释

> 只收录 PRD 中首次出现且读者可能不熟悉的专业术语。
> 业务通用概念已在项目背景中定义，不需要重复收录。
> 解释要简洁，一句话说清楚是什么、用在哪里。

| 名词 | 解释 |
|------|------|
| [术语] | [一句话解释：是什么 + 用在哪里] |

## 需求概述

### 需求背景

> 写作结构：现状是什么 → 存在什么问题 → 为什么现在要做
> 如果是二期/迭代需求，先说明一期做了什么、解决了什么，再说二期要解决什么。
> 长度控制：3-5 段，每段 2-4 句话。

### 需求目标

> 用短横线列表，每条一个目标，动词开头，说明做什么、达到什么效果。

- [目标1]
- [目标2]

### 需求价值 & 预估收益

> 用文字列表描述，不用表格。如果数据暂时无法量化，写"具体量化数据待上线后统计"。

- [价值点1]
- [价值点2]

### 本期功能清单

> 列填写说明：
> - 系统：填你自己的系统名
> - 顶级模块：一级菜单名称
> - 菜单：二级菜单路径，格式"一级/二级"；无页面功能填"—"
> - 功能：功能点名称，简短
> - 优先级：P0（核心必做）/ P1（重要）/ P2（可延后）
> - 测试范围：填"需测试" 或 "需开发支持"（纯后端/数据处理，无前端页面）
> - 功能描述：一句话说清楚这个功能做什么

| 系统 | 顶级模块 | 菜单 | 功能 | 优先级 | 测试范围 | 功能描述 |
|------|----------|------|------|--------|----------|----------|

> 风险项：简短命名，如"XX 稳定性""XX 数据不完整"
> 应对方案：当前的处理策略，可以是技术方案、流程约定，或"记为待办"

|--------|------|----------|
| | | |

## 功能框架

### 整体功能框架

> 用文字段落描述系统定位，再用短横线列表说明各层职责。不需要画架构图。

### 业务流程

> 流程图类型选择：
> - 多系统交互 → flowchart TD，用 subgraph 区分各系统
> - 接口调用时序 → sequenceDiagram
> - 状态流转 → stateDiagram-v2

> - 功能说明的描述，需要保障逻辑闭环
```

## 报表类需求专用模板

> 当需求核心是"查看聚合数据"而非"操作业务流程"时使用（如报表、统计、看板）。

```markdown
##### X.X.1 页面说明

**1. 字段说明**

| 字段 | 说明 | 示例 |
|------|------|------|
| **筛选区** | | |
| [字段名] | [控件类型]，[枚举值/查询方式]，默认[默认值] | |
| **列表区** | | |
| 字段参考报表口径 | 空值显示"—" | |

**2. 统计数据区**

| 区域 | 说明 |
|------|------|
| 合计-首行 | 置顶在表头下第一行，与表头全局固定。求和按当前查询结果单列求和。仅统计：[列出需要合计的字段] |

**3. 报表口径**

| 字段 | 口径 | 示例 |
|------|------|------|
| [字段名] | [数据来源 + 聚合维度 + 计算方式] | [示例值] |

**4. 数据规则**

- [通用规则，不重复口径中已说明的内容]

**5. 排序规则**

- [默认排序字段和方向]
```

### 报表类需求的关键规则

1. **查询/重置不写** — 框架基础能力，无需单独说明
2. **导出简化** — 只写"按当前筛选条件导出全部数据"一句话
3. **列表区字段简化** — 有报表口径时，列表区只写一行"字段参考报表口径"
4. **报表口径是核心** — 每个字段的计算逻辑、聚合维度都在口径表中说明
5. **统计数据区必写** — 有合计行时，必须说明位置（表头下方固定）和统计范围
6. **数据规则不重复** — 只写通用规则，不重复口径中已说明的内容
